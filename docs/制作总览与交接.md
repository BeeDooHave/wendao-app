# 《问道》制作总览与交接

> 版本：M1 入门仪式与首次入室定稿候选
> 更新日期：2026-05-27
> 用途：制作记录、新窗口接手、阶段验收与下一步排期

## 1. 项目定位

《问道》是一款把现实中的专注、学习、运动与休息，转写为修真叙事的 PWA。玩家并非靠点击获得修为，而是以真实完成的功课推动境界、环境与剧情变化。

核心体验承诺：

- 初次打开像踏入一场雨夜仙门故事，而不是直接面对任务表。
- 灵根只提供身份与叙事差异，道途来自玩家选择，不设置天赋强弱焦虑。
- 修行允许很轻地开始，也允许低谷与中断；断签不惩罚人格。
- 重要变化必须由真实行为触发，演出不能假装玩家已经修成。
- 数据和联网能力以用户授权、清晰说明和可迁出为原则。

一句话体验：**在一盏未熄的灯下，把现实中仍想守住的事，修成自己的道。**

## 2. 当前里程碑

### M1：入门仪式与首次入室

本阶段已形成可完整体验的开局流程：

1. 雨夜黑场字幕逐段推进，说明主角为何来到听雨山。
2. 山门显现，以「你想成为什么样的人？」收束序幕。
3. 闻钟先以灯火显形，再以全身画面和对话接引来者。
4. 玩家留下姓名或称呼，也可选择「暂不留名」，以「无名来者」入山。
5. 玩家在问心台自选灵根，或在测灵台离线排四柱，仅取日主五行作为游戏灵根。
6. 玩家选择剑、体、丹、符、阵之一道途。
7. 对应引路人以全屏过场现身，交谈后传授三卷初法。
8. 领受初法后，引路人身影隐入雨夜，余光引玩家进入静室。
9. 首页先作为「候行」场景显现；玩家确认开始今日修行后，修为与功课界面才露出。

此流程的关键原则是：**入室不等于完成修行**。后续剧情与成长反馈仍必须等待玩家亲手完成现实功课。

## 3. 当前已完成内容

### 3.1 入门与身份

- 黑屏点击式序幕、山门结尾画面与叩门操作。
- 闻钟接引剧情、称呼登记与匿名入山路径。
- 问心台自选五行灵根与五条道途。
- 测灵台本地历法计算：展示四柱，只以日主映射游戏灵根。
- 首批推荐功法模板与引路人授法对话。

### 3.2 引路人与授法演出

- 闻钟及五位道途引路人的全身竖屏画面。
- 暗场中以灯火、法器或明确光源先行揭示人物。
- 所有引路人使用同规格全屏过场，不混入缩小人物副图层。
- 初次授法后加入「余光引路 -> 静室候行 -> 首页释放」过场。

### 3.3 修行系统

- 计时、数量、守约三类功法及统一修为折算。
- 今日功课调度、主修、重复日、拖动排序。
- 一分钟起念入口与养息日低门槛收束。
- 闭关计时、后台切出处理、完成结算与连续修行记录。
- 引路人求法支持联网对话与离线回退；联网内容需经用户授权，结算仍由本地规则校验。

### 3.4 首页、境界与剧情

- 首页盘坐修行场景及灯火、雨幕、书案、气息反馈。
- 炼气法相四阶段表现。
- 筑基法相方案与叠加资产已经接入，仍需进一步实机视觉确认。
- 推演沙盒，可预览状态而不污染真实存档。
- 「未熄之灯」剧情首卷的世界、人物与行为节点框架。
- 入门与授法演出已接入；首次真实完成后的可见回应仍待重新设计。

### 3.5 声音、离线与数据

- 雨声、古琴、木鱼闭关声景与完成铜铃。
- PWA 离线缓存及本地存档。
- JSON 数据导入导出。
- 离线历法依赖随项目打包，隐私说明已保留直白表述。

## 4. 核心用户流程

### 4.1 首次进入

```text
打开 App
  -> 雨夜序幕字幕
  -> 山门初叩
  -> 闻钟接引并登记称呼
  -> 问心台 / 测灵台定灵根
  -> 选择道途
  -> 道途引路人显形与授法
  -> 余光引入静室
  -> 玩家主动开始今日修行
  -> 首页与真实功课循环
```

### 4.2 日常返回

```text
打开 App
  -> 首页环境承接上次真实进度
  -> 选择功课或一分钟起念
  -> 闭关 / 记录数量 / 确认守约
  -> 修为、环境和剧情节点回应
```

### 4.3 中断后归来

当玩家离开一段时间后，不以责备或损失作为第一反馈，而直接以大屏引导重新起念。目标是先重建行动，再恢复长功课节奏。

## 5. 叙事与文案定案

### 5.1 已定世界方向

- 山门：听雨山门。
- 主线意象：雨会冲淡念想，人的持守使灯未熄。
- 首位接引人：闻钟，守灯，也记录来者留下的名字。
- 玩家身份：入门来者，而非开局即有资格受道号之人。

详细设定见 [世界观与剧情设定.md](./世界观与剧情设定.md)。

### 5.2 用语规则

- 使用「姓名 / 称呼」，不使用「系统赐汝道号」。
- 初入山门默认称谓不可写成已经晋升的身份荣誉。
- 古意来自节奏、意象和克制，不来自让关键信息难懂。
- 隐私承诺必须明确写出：本机计算、不保存原始出生时间、不作现实命理解读。
- 不在演出中提前宣称玩家已完成修行、已引气或已获得真实成果。

### 5.3 已采纳的文案基调

- 「天赋为引，道途由心。道途不同，际遇自异；然修为深浅，终在己心。」
- 「闻钟展开灯册：来者，留下你的名字。」
- 「名字未必抵得住这场雨，却能让你记得，今夜为何上山。」
- 「真正的第一课，仍待你亲手开始。」

## 6. 技术实现摘要

### 6.1 技术形态

- 前端 PWA：`index.html`、`styles.css`、`app.js`、`sw.js`。
- 当前原型以本地存档为主；账号、同步和发行平台登录策略后续按需求接入。
- 当前缓存版本：`wendao-v0.57-mentor-chat`。
- 四柱计算依赖本地打包的 `vendor/lunar.js`，许可见 `vendor/lunar-LICENSE.txt`。

### 6.2 关键目录

| 路径 | 作用 |
|---|---|
| `assets/mentors/` | 闻钟与五位引路人全屏过场画面及概念图 |
| `assets/audio/` | 闭关声景和完成音效 |
| `assets/generated/` | 法相等生成型效果资产 |
| `docs/` | 制作、世界观、体验、美术与素材许可文档 |
| `vendor/` | 随应用离线使用的第三方依赖及许可 |

### 6.3 重要状态与兼容策略

| 状态 | 含义 |
|---|---|
| `identity` | 灵根、道途、称呼来源及可选四柱结果 |
| `storySeen` | 已观看的关键剧情节点 |
| `initiationSeen` | 是否看过首次受法后的入室演出 |

新增 `initiationSeen` 时，对旧存档默认视为已观看，避免既有玩家突然被强制重播开局过场；新入门玩家则只观看一次。

## 8. 下一阶段路线

### P0：本里程碑封版校验

- 在手机窄屏与较长屏幕上确认六位人物全屏裁切、灯光锚点和对话框不遮住关键面部/法器。
- 从全新存档完整跑一遍五道途，确认入室演出只在首次授法播放一次。
- 检查 PWA 离线重新打开、数据导出导入与旧存档迁移表现。

### P1：真实修行后的第一份叙事回报

- 设计首次真实完成后的可见回应，让玩家明确感到行动被山门记录。
- 寻找替代「雨痕退寸」的新意象；该方案已回溯，不再作为当前方向。
- 完善第一周七日节奏：轻量日、回归日与第一次长线承诺。

### P2：引路人求法与功法成长

- 完善引路人授法协议：候选功法需经过本地规则校验，后续加入用量限制与公开发行所需身份认证。
- 不诱导过度时长，不对健康或命理作现实断言，并给玩家修改确认权。
- 将功法从「模板」扩展为可成长、可留下修炼记忆的个人技艺。

### P3：破境与长期世界

- 验证筑基视觉并制作金丹及后续境界资产。
- 制作筑基之约、突破文书和更明显的首页环境阶段变化。
- 扩写宗门人物关系、事件分支与机缘录。

## 9. 尚待决定的问题

- 「打卡功法」是否需要独立存在，还是由计时、数量、守约三类已充分覆盖日常记录。
- 引路人联网能力、费用、身份认证与同步策略如何组合。
- 是否提供「重温入门过场」入口，且如何与真实新档体验区分。
- 环境反馈在安静克制与明显奖励之间的最终力度。
- 数据同步是否始终保持可选且不破坏离线优先承诺。

## 10. 验收清单

### 开局与演出

- 新存档进入时先见序幕，不直接落到首页。
- 文案没有「系统赐道号」或不合资格的默认身份。
- 闻钟及五引路人均为单一全屏人物图层。
- 灯光与图片内光源在常见屏幕比例下对得上。
- 初次授法后存在入室承接，首页不会生硬闪现。
- 入室文本不误称功课已经完成。

### 行为与数据

- 一分钟起念可正常开始并按规则结算。
- 数量与守约功法不会重复发放修为。
- 中断归来可直接进入低门槛启动。
- 测灵台只保留必要结果，隐私提示清楚可见。
- 旧存档不会意外重新播放首次入室演出。

### 发布前

- JavaScript 语法检查通过。
- `git diff --check` 无空白错误。
- 本地预览可打开，关键 CSS、JS 和 Service Worker 资源可加载。
- 新存档及已有存档路径至少各手测一次。
